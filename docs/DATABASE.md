# Database Design

## Collections

### 1. Users
Stores user account information.

### 2. Subjects
Stores all subjects created by the user.

### 3. Topics
Stores study topics under each subject.

### 4. Revisions
Stores all scheduled revisions generated for every topic.

---

## Relationships

One User → Many Subjects

One Subject → Many Topics

One Topic → Many Revisions

# Users Collection

### Purpose

Stores user account information and authentication details.

| Field | Type | Description |
|--------|------|-------------|
| _id | ObjectId | Unique user ID |
| name | String | User's full name |
| email | String | User's email address (unique, lowercase) |
| password | String | Hashed password using bcrypt |
| avatar | String | Profile image URL |
| isEmailVerified | Boolean | Indicates whether the user's email has been verified |
| streak | Number | Current revision streak |
| longestStreak | Number | Highest revision streak achieved |
| createdAt | Date | Record creation timestamp |
| updatedAt | Date | Record last updated timestamp |


## Default Values

| Field | Default Value |
|--------|---------------|
| avatar | "" |
| isEmailVerified | false |
| streak | 0 |
| longestStreak | 0 |

## Notes

- Email must be unique.
- Password is stored as a bcrypt hash.
- User cannot log in until `isEmailVerified` is `true`.

# Subjects Collection

## Purpose

Stores all subjects created by a user.

| Field | Type | Required | Description |
|--------|------|----------|-------------|
| _id | ObjectId | Yes | Unique subject identifier generated by MongoDB |
| userId | ObjectId | Yes | References the owner of the subject |
| name | String | Yes | Subject name (e.g., DSA, DBMS, Operating System) |
| color | String | No | Color used for UI representation |
| description | String | No | Optional description of the subject |
| createdAt | Date | Yes | Subject creation date |
| updatedAt | Date | Yes | Last updated date |

-------------------------------------------------------------

# Topics Collection

## Purpose

Stores topics under a subject and tracks their learning progress.

| Field | Type | Required | Description |
|--------|------|----------|-------------|
| _id | ObjectId | Yes | Unique topic identifier generated by MongoDB |
| userId | ObjectId | Yes | References the owner of the topic |
| subjectId | ObjectId | Yes | References the subject this topic belongs to |
| name | String | Yes | Topic name (e.g., Binary Search Tree) |
| difficulty | String | Yes | Easy / Medium / Hard |
| masteryLevel | Number | Yes | Learning progress (0–100%) |
| totalRevisions | Number | Yes | Number of completed revisions |
| lastRevisedAt | Date | No | Date of the last completed revision |
| notes | String | No | Optional notes for the topic |
| createdAt | Date | Yes | Topic creation date |
| updatedAt | Date | Yes | Last updated date |
| isArchived| Boolean| Yes| Indicates whether the topic is archived instead of permanently deleted

# Revisions Collection

## Purpose

Stores every revision session and powers the spaced repetition system.

| Field | Type | Required | Description |
|--------|------|----------|-------------|
| _id | ObjectId | Yes | MongoDB generated ID |
| userId | ObjectId | Yes | Owner of the revision |
| subjectId | ObjectId | Yes | Related subject |
| topicId | ObjectId | Yes | Related topic |
| revisionNumber | Number | Yes | 1st, 2nd, 3rd... revision |
| scheduledDate | Date | Yes | When the revision should happen |
| completedAt | Date | No | When the revision was completed |
| rating | String | No | Easy / Somewhat / Forgot |
| createdAt | Date | Yes | Creation time |
| updatedAt | Date | Yes | Last update |
